日期：2026-10-08。状态：目标、范围、恢复行为与完整方案均已获用户确认，探索阶段完成，功能改动尚未实施。

## 已确认决定

- 优化以可靠性为主、使用体验为辅（用户接受第一轮推荐）。
- 产品技术路线固定为 Tauri，终止替代技术路线讨论。见 [ADR 0001](../adr/0001-retain-tauri-for-product-ui.md)。
- 延续当前 macOS 优先范围；本轮没有新增平台或历史功能的交付承诺。
- 本轮可靠性范围：SSH、SFTP、凭据恢复及 SSH 请求入队阻塞候选的复现与修复；用户接受第二轮推荐。
- 本轮体验范围：上述流程的失败原因、恢复入口和状态一致性。
- 隧道、Telnet、物理串口的完整验收单独列后续；托管密钥关联与跨分片触发器匹配列后续产品增强候选，不计入本轮承诺。
- 输入超时立即持续提示并暂停受影响终端的新输入，提供手动重连，不自动重放命令；执行结果不确定时如实说明。
- 上传下载先写临时文件，成功后提交最终目标；覆盖仍需明确确认。失败或取消说明残留和清理结果，重试从头开始。见 [ADR 0002](../adr/0002-stage-transfers-before-target-commit.md)。
- 完成状态分为开发验证完成与产品验收完成，后者须具备本轮 macOS 实机证据。

## 第三轮已确认行为与现状差距

- SSH 输入超时后的请求处置与恢复：采用立即持续提示、暂停新输入、手动重连且不重放。`client.rs:877-879` 尚未检查请求是否过期，超时后仍可能继续发送；`TerminalPane.vue:352-367` 连续三次失败才提示且文案称未送达，需同步修正。
- SFTP 中断后的目标文件：采用临时文件成功后提交、保留旧目标、显示残留处理结果、从头重试。当前上传 `sftp.rs:267` 与下载 `:321` 直接创建最终目标；失败和取消不执行临时提交或清理，需要实现完整生命周期。
- 本轮验收门槛：采用开发验证与产品验收两个完成状态，当前 Windows 环境的自动化不能替代 macOS 钥匙串、原生交互和真实服务器证据。

## 恢复流程补充核对

- `rshell-core/src/session/service.rs:235-240` 合并凭据读取错误，不能据此区分条目缺失与钥匙串不可访问。已有更新凭据与重试加载入口，应补充原因分类和直接引导，不混淆两类恢复操作。
- `src/stores/hostKey.ts:38-46` 用单个 `current` 保存确认请求，并发新请求会覆盖旧请求；后端取消决策后，前端缺少对应过期同步。`HostKeyMismatchDialog.vue` 禁止普通关闭，失效请求可能留在弹窗内。作为 SSH 状态一致性问题纳入本轮，保留逐次人工确认和永久信任先落盘的底线。
