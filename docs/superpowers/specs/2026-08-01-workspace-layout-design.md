## 1. 背景与问题定义

最近一次 v2 视觉改版已经建立了“标题栏 → 工作区工具栏 → 左侧导航/面板 → 主工作区 → 状态栏”的基础骨架，并接入终端工作区、SFTP 双窗格和传输队列。但当前实现仍存在三个直接影响空间效率和信息层级的问题：

1. `ActivityBar` 的职责是窄导航条，实际宽度却为 220px；它与 320px 的 `SidePanel` 叠加后，默认占据约 540px 的左侧空间。
2. 功能入口位于左侧，和会话树、密钥、工具等上下文内容混在同一方向，用户在终端和传输工作区之间切换时需要横向寻找入口。
3. `SidePanel` 中的工具和设置会把多个业务组件纵向堆叠，导致快速命令、触发器、隧道、主题和插件在有限宽度/高度内互相竞争。

本设计将左侧区域收敛为单一的、可调整宽度的上下文面板，并把功能导航移到顶部横向工具栏。终端或传输主工作区始终作为主要内容区域保留。

---

## 2. 目标与非目标

### 2.1 目标

- 将工作区和功能入口统一到顶部横向工具栏。
- 保留左侧面板的可读性和会话树上下文。
- 侧栏默认宽度为 280px，可在 200–360px 之间拖动调整。
- 侧栏折叠后完全隐藏，不保留窄图标条或手柄。
- 工具、设置等复合功能在侧栏内使用二级切换，一次只显示一个子面板。
- 切换顶部功能入口时保留当前终端或传输主工作区。
- 不改变现有 Tauri IPC、Pinia 数据模型和后端业务契约。
- 遵循现有 token、无障碍、动效和错误提示规范。

### 2.2 非目标

本轮不包含：

- 布局宽度或面板状态持久化。
- 将侧栏和管理面板迁移为 Dockview 可停靠视图。
- 新增或修改 Rust 命令、事件、API 类型。
- 补齐密钥、工具、插件或传输队列的业务能力。
- 接入真实传输队列数据或重写现有 IPC 错误映射。
- 全面替换当前图标实现。
- 删除历史 `ActivityBar.vue` 文件。

## 3. 已确认的用户体验决策

以下决策已经通过视觉线框和逐段确认：

| 决策 | 结果 |
|---|---|
| 顶部/左侧导航关系 | 功能工具栏移到顶部横向排列；左侧只显示当前上下文面板 |
| 管理类功能位置 | 密钥、快速命令、触发器、隧道、主题、插件均替换左侧上下文内容；主终端/传输区保持可见 |
| 侧栏宽度 | 默认 280px，可拖动到 200–360px |
| 侧栏折叠 | 完全隐藏；通过顶部按钮、视图菜单或既有快捷键重新打开 |
| 复合面板 | 工具和设置各自提供二级切换，一次只显示一个子面板 |
| 状态持久化 | 本轮不保存到磁盘或后端；刷新后恢复默认宽度和初始布局 |

## 4. 总体布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ CustomTitleBar · 32px                                             │
├────────────────────────────────────────────────────────────────────┤
│ WorkspaceToolbar · 40px                                           │
│ [终端][传输] · [会话][文件][密钥][工具][设置] · [常用操作] · 状态   │
├──────────────────────────┬─────────────────────────────────────────┤
│ SidePanel                 │ MainArea                                │
│ 默认 280px                │ Terminal Workspace / Transfer Workspace │
│ 可调 200–360px            │                                         │
│ 当前上下文内容            │                                         │
├──────────────────────────┴─────────────────────────────────────────┤
│ StatusBar · 24px                                                  │
└────────────────────────────────────────────────────────────────────┘
```

### 4.1 顶部区域

- `CustomTitleBar` 继续负责窗口拖动、菜单和窗口控制，保持 32px 高度。
- `WorkspaceToolbar` 继续负责工作区操作，保持 40px 高度，但扩展为三组：
  1. **工作区组**：终端 / 传输；
  2. **上下文组**：会话 / 文件 / 密钥 / 工具 / 设置；
  3. **操作组**：根据当前工作区显示连接、查找、清屏、上传、下载、刷新、传输队列等动作。
- 顶部增加独立的侧栏切换按钮。按钮必须有 `aria-pressed`，并与 `CustomTitleBar` 的“视图 → 切换侧边栏”共用同一事件。
- 空间不足时上下文按钮以图标为主，完整名称通过 Tooltip 提供；终端和传输的核心操作不能因压缩而消失。

### 4.2 左侧上下文面板

- `SidePanel` 是左侧唯一的面板容器，不再与 `ActivityBar` 并列。
- 默认宽度 280px，最小 200px，最大 360px。
- 面板只渲染当前 `activePanel` 对应的内容：
  - `sessions`：`SessionList`；
  - `files`：文件浏览上下文；
  - `keys`：`KeyManagerPanel`；
  - `tools`：工具二级面板；
  - `settings`：设置二级面板。
- 面板标题只保留一层。外层 `SidePanel` 负责标题、折叠入口和二级切换；`SessionList`、`KeyManagerPanel`、`QuickCommandPanel`、`TriggerEditor`、`TunnelPanel`、`ThemePanel` 和 `PluginPanel` 应提供嵌入侧栏的无重复标题呈现方式（通过 prop、slot 或等效结构实现），不得再重复渲染相同的面板标题。
- 侧栏右边缘提供约 5px 的拖拽 separator。拖拽区不能覆盖会话行、表格或输入控件。
- 侧栏隐藏时从布局中移除宽度，主工作区获得全部剩余空间；不保留 40px 手柄或图标条。

### 4.3 主工作区

- `main-area` 继续占据剩余空间，并保持 `min-width: 0`、`min-height: 0`，避免终端或双窗格撑出整体滚动条。
- 终端工作区继续使用 Dockview 多终端；传输工作区继续使用双窗格和底部传输面板。
- 顶部上下文面板切换不得重置主工作区：当前终端会话、终端标签、SFTP 路径、同步开关和传输面板展开状态必须保持。
- 工作区切换也不得丢失当前会话选择；如果实现需要重新挂载视图，必须将工作区局部状态提升或使用等效的保活机制。

### 4.4 底部状态栏

- `StatusBar` 继续固定在底部，保持现有 24px 几何 token。
- 根据 `workspace` 显示 SSH 或 SFTP 协议摘要，现有连接状态点和会话名称逻辑不变。
- 布局优化不新增状态字段，也不改变后端状态来源。

## 5. 组件与状态设计

### 5.1 组件职责

| 组件 | 本轮职责 | 不负责的内容 |
|---|---|---|
| `App.vue` | 持有工作区、当前面板、侧栏展开态、侧栏宽度和拖拽状态；协调顶部与侧栏事件 | 业务 IPC 细节、管理面板内部数据加载 |
| `WorkspaceToolbar.vue` | 展示三组顶部入口；发出工作区、面板、侧栏和操作事件 | 直接写 Pinia 或调用后端服务 |
| `SidePanel.vue` | 渲染单一上下文面板；提供标题、二级 tab 和 separator | 管理业务数据、重复渲染 ActivityBar |
| `SessionList.vue` | 继续负责会话过滤、树、连接状态和右键菜单 | 布局宽度和顶部导航 |
| `KeyManagerPanel.vue` | 继续负责密钥列表和现有 IPC 操作 | 外层侧栏导航 |
| `QuickCommandPanel.vue` / `TriggerEditor.vue` / `TunnelPanel.vue` | 一次只显示一个工具子面板 | 同时管理其他工具子面板 |
| `ThemePanel.vue` / `PluginPanel.vue` | 一次只显示一个设置子面板 | 同时管理其他设置子面板 |
| `ActivityBar.vue` | 从 `App.vue` 主布局移除；文件暂不删除 | 新布局中的必需渲染职责 |

### 5.2 App 层状态

建议在 `App.vue` 保持以下本地状态，命名可按现有代码风格调整：

```ts
type WorkspaceKind = "terminal" | "transfer";
type PanelKind = "sessions" | "files" | "keys" | "tools" | "settings";
type ToolSubview = "quick-commands" | "triggers" | "tunnels";
type SettingsSubview = "theme" | "plugins";

const workspace = ref<WorkspaceKind>("terminal");
const activePanel = ref<PanelKind>("sessions");
const panelExpanded = ref(true);
const sidebarWidth = ref(280);
const activeToolSubview = ref<ToolSubview>("quick-commands");
const activeSettingsSubview = ref<SettingsSubview>("theme");
```

- 点击顶部上下文按钮：更新 `activePanel`，并将 `panelExpanded` 设为 `true`。
- 点击侧栏按钮：只切换 `panelExpanded`，不改变 `activePanel`。
- 切换工具或设置二级 tab：只更新对应 subview，不影响 `workspace`、会话选择或主工作区。
- `sidebarWidth` 是临时 UI 状态，不写入 IPC 或后端存储。

### 5.3 复合面板渲染

工具面板标题区使用 segmented control：

```text
工具                                  [快速命令] [触发器] [隧道]
```

设置面板标题区使用 segmented control：

```text
设置                                  [主题] [插件]
```

每组二级面板必须通过条件渲染、动态组件或等效机制保证同一时刻只有一个子面板可见。切换时保留现有组件的错误提示和加载状态语义，不吞掉 IPC 错误。

## 6. 交互行为

### 6.1 面板选择与工作区切换

1. 用户点击顶部的终端或传输：更新 `workspace`，不清空当前会话或传输状态。
2. 用户点击会话、文件、密钥、工具或设置：更新 `activePanel`，自动展开侧栏，主工作区保持原状态。
3. 用户再次点击当前上下文按钮：不自动折叠侧栏；折叠只由独立的侧栏按钮、视图菜单或快捷键触发。
4. 从 `SessionList` 执行“打开 SFTP”：切换到传输工作区并选择对应会话，侧栏状态按当前面板规则保留。
5. 从 `SessionList` 执行“在此打开终端”：切换到终端工作区，不改变会话树的选中项。

### 6.2 侧栏调整

- 鼠标按下 separator 后开始拖拽，使用窗口坐标计算宽度。
- 宽度始终 clamp 在 200–360px；非有限坐标或容器宽度时回退到当前有效宽度。
- 拖拽期间显示 `col-resize`，鼠标释放、离开窗口或组件卸载时清理全局监听。
- separator 双击将宽度恢复到 280px。
- separator 可聚焦并提供 `role="separator"`、`aria-orientation="vertical"`、`aria-valuemin="200"`、`aria-valuemax="360"`、`aria-valuenow`。
- 键盘左右方向键以 8px 为步长调整宽度；Home/End 可分别跳到最小/最大值（若实现采用不同快捷键，必须保持可发现性并在 Tooltip 中说明）。
- 展开/折叠过渡使用约 250ms，与现有动效 token 保持一致；拖动本身不使用延迟动画，避免跟手性变差。

### 6.3 响应式规则

- 常规窗口使用 280px 默认宽度。
- 窗口宽度小于 900px 时，侧栏仍可调整到 200px；在窗口空间足够时，上限取 `min(360px, viewportWidth - 360px)`，其中 360px 是主工作区的优先目标而不是硬性最小值。
- 当 `viewportWidth - 360px` 小于 200px 时，将拖拽上限收敛为 200px，允许主工作区暂时窄于 360px，但不产生页面级水平溢出；侧栏始终提供完全隐藏路径，隐藏后主工作区获得全部可用宽度。
- 小窗口顶部按钮优先保留图标和 Tooltip；工作区切换、侧栏切换和当前工作区核心动作始终可用。
- 不增加页面级水平或垂直滚动条；滚动只出现在面板内容、文件列表、传输列表和终端内部。

### 6.4 无障碍与视觉反馈

- 新增或改造的按钮必须有可见 Tooltip、`aria-label` 和键盘焦点样式。
- 当前工作区和当前上下文按钮使用激活背景与底部 accent 线，不能只依赖颜色区分。
- separator 的悬停/聚焦状态使用 accent 色，并保留足够的可操作命中区域。
- 复用现有连接状态点：灰色未连接、黄色连接中、绿色已连接、红色失败。
- 延续 4px 间距基准、现有 `--rs-*` token、UI/Mono 字体栈和 100–250ms 过渡规范。

## 7. 数据流与错误处理

### 7.1 数据流边界

本轮不新增 IPC 命令、事件或后端类型：

```text
顶部交互
  → App.vue 更新本地布局状态
  → WorkspaceToolbar / SidePanel 重新渲染
  → 现有业务组件调用 Pinia 与 src/ipc/client.ts
  → 现有事件订阅更新会话、连接、主题和传输状态
```

布局状态只存在前端。侧栏拖拽不会触发 `invoke`、`emit` 或后端事件。

### 7.2 错误边界

- 拖拽监听必须在 `onBeforeUnmount` 中清理，避免切换组件后残留全局事件。
- 宽度计算失败时回退当前有效值，不能将 `NaN`、负数或超出范围的值写入样式。
- 面板 IPC 加载失败继续由现有业务组件以内联错误呈现；切换面板不得阻塞顶部导航。
- 工具/设置二级切换不得清除其他面板已产生的错误或加载状态，除非组件自身卸载语义明确要求如此。
- 不新增静默 catch，不改变现有错误文本、日志级别或后端错误映射。

## 8. 实施范围与建议文件

实施计划应优先覆盖以下文件：

1. `src/App.vue`：移除 `ActivityBar` 布局节点，增加侧栏宽度/拖拽状态和顶部面板事件协调；保证工作区状态不因侧栏切换丢失。
2. `src/components/WorkspaceToolbar.vue`：增加上下文入口和侧栏切换按钮，补充 active/ARIA/Tooltip 状态。
3. `src/components/SidePanel.vue`：重构为单一上下文容器，加入工具/设置二级切换和 separator。
4. `src/styles/tokens.css`：将侧栏默认/最小/最大宽度和必要的 separator 几何量集中到 token；保持旧别名兼容。
5. `src/styles/global.css`：仅在需要时补充布局/焦点/响应式基础样式。
6. `tests/unit/`：增加布局状态、宽度 clamp、子面板互斥和 ARIA 行为测试。
7. `src/components/ActivityBar.vue`：本轮不删除；若编译器或 lint 无引用告警，再由后续清理任务处理。

不得因为本轮布局优化而修改 `src-tauri/`、`src/ipc/types.ts` 或后端业务 crate。

## 9. 验收标准

### 9.1 自动化验证

以下命令必须通过：

```bash
npm run typecheck
npm test
npm run build
```

新增测试至少覆盖：

1. 顶部导航渲染，`ActivityBar` 不再出现在主布局中。
2. 点击五个上下文入口时 `activePanel` 更新且侧栏自动展开。
3. 侧栏按钮可完全隐藏并重新打开。
4. 宽度拖拽 clamp 到 200–360px，双击恢复 280px。
5. separator 键盘操作更新宽度和 ARIA 值。
6. 工具和设置一次只显示一个二级子面板。
7. 侧栏/上下文切换不改变当前工作区、会话选择或传输面板状态。

### 9.2 手工验收

在至少以下窗口尺寸检查：

- 1280×800：默认 280px、终端和传输工作区层级清晰；
- 1024×768：侧栏 200px、280px、360px 均可用；
- 宽度小于 900px：顶部按钮不溢出，侧栏可隐藏，主区仍可操作；
- 侧栏隐藏：主区完全接管可用空间；
- 终端与传输切换：当前会话、SFTP 路径、同步状态和队列展开状态不丢失；
- 工具/设置二级切换：无纵向堆叠、无重复标题；
- 键盘 Tab、方向键、Home/End 和 Tooltip：入口可发现且焦点可见；
- 连接中、连接失败、无会话、IPC 加载失败：状态点和错误信息仍正确显示。

## 10. 后续可选工作

以下事项明确留待独立变更，不阻塞本轮实现：

- 持久化侧栏宽度和每个工作区的布局偏好；
- 将工具栏按钮做成用户可配置集合；
- 引入统一的 `useWorkspaceLayout()` 状态组合式函数；
- 删除不再使用的 `ActivityBar.vue`；
- 以 Dockview 或其他停靠机制支持管理面板自由布局。
