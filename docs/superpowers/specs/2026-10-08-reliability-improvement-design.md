状态：用户已于 2026-10-08 确认整份方案的共同理解；SSH 部分已实施并完成任务范围验证，当前按用户要求暂停。独立审查、其余任务与产品验收尚未完成。恢复入口见 [实施进度](../plans/2026-10-08-reliability-recovery-progress.md)。

## 目标与范围

继续使用 Tauri、Vue、TypeScript 和 Rust，以可靠性为主、使用体验为辅，优先保证 macOS 上现有功能可解释、可恢复、可验证。

本轮覆盖 SSH 输入与标签生命周期、SFTP 文件保护与任务结果、凭据缺失和不可访问时的恢复，以及对应的失败提示和状态一致性。

隧道、Telnet 和物理串口的完整验收另行安排；托管密钥关联连接、跨分片触发器匹配、跨连接断点续传和签名公证均不作为本轮完成条件。替代 UI 框架的讨论已结束。

## 依据与现状

静态代码调查发现：SSH actor 请求队列容量为 32，发送、resize 和关闭的入队等待未被已有应答超时覆盖。actor 等待远端写入时若队列饱和，新请求可能卡在应答计时开始之前；此候选尚未完成运行时复现。

应答超时只结束调用方等待，不足以证明远端未收到输入。当前终端连续三次 I/O 失败才提示，文案称“未送达”，无法准确表达超时后的不确定结果。

SFTP 当前直接创建最终目标，失败或取消可能留下不完整文件，覆盖可能提前截断旧文件。现有暂停与恢复是在同一个活跃任务内继续拷贝，不等于断线后的断点续传。

凭据已有钥匙串存储、迁移失败报告和“更新凭据”入口。主要待补的是错误原因与恢复入口的连贯性，以及 macOS 实机证据；不重建凭据保险库。

主机密钥确认使用单个前端当前请求，并发请求可能覆盖，后端决策过期也缺少前端同步。需完善其请求生命周期，保持已有人工信任规则。

证据路径、历史验收边界与访谈决定见 [探索记录](../../research/2026-10-08-project-improvement-exploration.md)。术语见 [CONTEXT.md](../../../CONTEXT.md)。

## 一、SSH 请求有界与终端恢复

### 用户行为契约

- 输入超时立即显示持续提示，不等待连续失败阈值。提示区分确定拒绝与结果不确定，不把超时写成“远端未执行”。
- 暂停受影响标签会话的新输入，提供手动重连入口，不自动重放键盘输入、粘贴文本或命令。
- 重连建立真实可用终端后才恢复输入。重连失败继续显示原因与可操作入口。
- 同一连接的其他标签是否受影响，以实际后端故障范围决定；不能仅用前端局部恢复掩盖共享连接不可用。
- 关闭标签、断开连接和后续连接操作应在有界时间内返回，不要求用户重启整个应用。重连不承诺恢复远端原进程，也无法撤销已发送的字节。

### 实施约束

- 先构造停滞 actor 与饱和队列复现，再修正排队、执行和拆除的等待范围；不能只在最外层包装超时并留下仍可能执行的队列请求。
- 为尚未执行的过期输入建立可验证的丢弃机制；已执行或部分发送的输入保持结果不确定，恢复前隔离或结束旧终端路径。
- 沿用现有业务层、协议层和 Tauri 薄壳职责，不在 UI 内模拟连接状态。输入不可用状态应与连接状态区分。
- 后续实施计划明确端到端等待预算与测试注入方式。现有 10 秒应答限制可作为起点，不能将它误称为已经覆盖完整生命周期。

### 验收条件

- 对端停止读取、队列饱和时，输入、resize、关闭和断开均在规定预算内返回。
- 一次输入超时即可看到持续错误和恢复入口；结果不确定时文案不声称未执行。
- 已过期且尚未开始的输入不会在对端恢复后被悄悄发送。
- 手动重连成功后输入恢复，旧终端请求不进入新终端；失败时状态不伪装为可用。
- 重复关闭、超时与关闭竞争、关闭后晚到事件有回归覆盖；其他可用连接不会被故障终端阻塞。

## 二、SFTP 临时文件与最终提交

### 用户行为契约

- 上传和下载先写临时传输文件，传输和最终提交成功后才显示完成。目标内容在提交前不因传输失败被截断。
- 覆盖仍需明确确认；目标在预检后出现或变化时，提交阶段必须重新执行冲突策略。
- 失败或取消后，说明原目标是否保留、临时文件是否清理，以及无法清理的确切路径和原因。
- 重试创建新任务，从头传输，不自动覆盖；既有活跃任务内暂停/继续的语义保留。
- 移除队列记录不删除文件，清理临时文件不扩大为目录清理。

### 实施约束

- 临时文件须独占创建、可归属到当前任务，并放在适合最终提交的位置；本地和远端路径分别验证。
- 检查远端重命名、替换和冲突检测能力，验证本地提交语义。无法保证安全提交时明确失败并保留旧目标，不回退到先删除旧文件或直接截断目标。
- 把写入、关闭或刷新、最终提交、清理的错误分别保留；100% 字节进度不代表提交已经成功。
- 取消与最终提交必须有明确的先后裁决，避免“已取消”任务随后替换目标，或已提交成功却报告为取消。该裁决由实现与回归测试共同保证。
- 清理仅处理当前任务确认拥有的临时文件。清理失败可见；进程崩溃后的跨进程扫描和自动清理另行规划。

### 验收条件

- 上传与下载均覆盖新目标和明确授权覆盖目标；成功后内容一致，并无属于该任务的临时文件残留。
- 写入失败、断网、磁盘或权限失败、取消时，已有最终目标内容保持不变；临时残留与清理失败被真实报告。
- 最终提交失败不发布完成事件，原目标仍受保护。
- 目标在预检后出现、清理失败、取消与提交竞争均有定向回归。
- 重试、暂停/继续、取消和移除记录的界面动作与实际任务状态一致。

## 三、凭据恢复与错误反馈

### 用户行为契约

- 区分凭据条目缺失、钥匙串不可访问、认证被拒绝、网络失败和主机密钥待确认等原因，给出对应操作建议。
- 凭据缺失指向既有“更新凭据”入口；存储访问问题提示修复钥匙串访问后重试；保存失败不提示成功或擅自建立连接。
- 不回退到旧明文、不展示已存储秘密、不记录密码或口令。主机密钥决定仍由用户作出，永久信任保存失败时不接受握手。
- 并发主机密钥确认保留各自请求和主机指纹，不互相覆盖；后端已取消或过期的请求明确失效并允许关闭，不能再执行信任。未过期的请求维持原有明确拒绝或信任流程。
- 单次操作可见的错误只保留必要上下文；详细诊断保留原因但不包含输入文本与秘密。

### 验收条件

- 缺失条目 → 可见原因 → 更新凭据 → 保存成功 → 手动重连成功形成可验证流程。
- 钥匙串拒绝访问、保存失败、旧配置迁移失败均显示真实原因并保留恢复路径。
- 修改凭据后再次认证失败时不宣称已连接；取消编辑不改写秘密。
- 原有主机密钥确认、永久信任落盘与迁移保留行为保持回归覆盖。
- 同时连接多个未知主机、确认期间取消连接、确认超时、提交决策与新请求并发均有回归；一个请求的提交结果不能清除其他仍有效请求。
- macOS 原生钥匙串提示、真实旧配置迁移和缺失条目恢复单独记录实机结果。

## 实施顺序

1. 建立故障复现和验收矩阵，确认当前候选及基线，保留已有通过结果与本轮新结果的区别。
2. 修正 SSH 请求生命周期与超时后处置，再接通持续提示、输入限制和手动重连。
3. 实现 SFTP 临时传输、提交与清理的完整生命周期，同步任务状态、错误详情和重试入口。
4. 完善凭据恢复与错误分类，检查 Rust API、TypeScript、Tauri handler 和调用方的一致性。
5. 运行对应定向回归，再运行共享质量门禁；最后完成 macOS 实机流程并更新验证记录。

每一步仅在实现与关联检查有证据后标记完成；发现候选不成立时记录复现结论，不为原假设强行改代码。
