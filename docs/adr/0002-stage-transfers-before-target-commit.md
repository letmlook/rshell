# 先完成临时传输，再提交最终目标

2026-10-08，用户确认本轮 SFTP 优化采用临时文件传输、成功后提交最终目标的方式，覆盖仍需明确确认。该方案增加提交与临时文件清理的复杂度，但可避免当前直接写入目标在失败或取消时留下半文件、提前截断旧文件。失败需说明残留临时文件及处理结果；本轮重试从头开始，跨连接断点续传另行规划。

## 后续验证

本决定确立文件保护的目标，不代表当前实现已经支持它，也不假设所有服务器具备相同的原子替换能力。实施时必须验证远端提交语义，不能通过先删除旧目标再重命名来伪装成安全替换；无法安全提交时应保留旧目标并明确报告失败。
