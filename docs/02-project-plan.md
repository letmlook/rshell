## 1. 项目范围与边界定义

### 1.1 项目范围（In Scope）

| 功能域 | 包含内容 | 参考设计文档 |
|--------|----------|--------------|
| 终端仿真 | SSH2/Telnet/Serial/RDP 终端连接、VT100-320 仿真、Unicode | §3.1, §3.2 |
| 文件传输 | SFTP/FTP/FTPS 双窗格管理、拖放、断点续传、同步 | §3.4 |
| 会话管理 | 会话树、属性继承、认证配置、跳转主机 | §3.3 |
| 安全 | 密钥管理、主密码、隧道/端口转发、SOCKS | §3.5 |
| 效率工具 | 快速命令、撰写窗格、同步输入、触发器、脚本引擎 | §3.7 |
| UI 框架 | Dock 布局、主题/配色方案、标签/分屏 | §3.6 |
| 插件系统 | Plugin SDK、WASM 沙箱、扩展点 | §3.8 |

### 1.2 项目边界（Out of Scope）

| 排除项 | 说明 |
|--------|------|
| SSH1 协议 | 已过时，存在安全隐患 |
| VNC 协议 | 不在 Xshell/Xftp 功能范围内 |
| 移动端（iOS/Android） | 仅桌面平台 |
| 服务端/守护进程模式 | 仅客户端工具 |
| 数据库管理工具 | 非终端/文件管理范畴 |
| 即时通讯集成 | 非本项目目标 |

### 1.3 目标平台

| 平台 | 优先级 | 最低版本 |
|------|--------|----------|
| Windows | P0 | Windows 10 21H2+ (x64) |
| macOS | P0 | macOS 12 Monterey+ (Apple Silicon + Intel) |
| Linux | P1 | Ubuntu 22.04+ / Fedora 38+ (x64, Wayland/X11) |

## 2. 里程碑与交付节点

### 2.1 里程碑总览

| 里程碑 | 阶段 | 时间 | 交付物 | 验收标准 |
|--------|------|------|--------|----------|
| M1 | Phase 1: MVP 核心终端 | W1-W10 (10 周) | 可 SSH 连接的终端应用 | SSH 登录成功，多标签可用 |
| M2 | Phase 2: 文件传输 | W11-W18 (8 周) | SFTP 文件管理器 | 文件上传/下载/同步可用 |
| M3 | Phase 3: 效率工具 | W19-W26 (8 周) | 自动化功能 | 快速命令/触发器/脚本可用 |
| M4 | Phase 4: 安全与隧道 | W27-W32 (6 周) | 安全功能 | 密钥管理/隧道可用 |
| M5 | Phase 5: 多协议完善 | W33-W40 (8 周) | 全功能版本 | Telnet/Serial/RDP/主题可用 |
| M6 | Phase 6: 插件生态 | W41-W46 (6 周) | 可扩展平台 | 插件 SDK/WASM 沙箱可用 |

### 2.2 详细交付计划

#### Phase 1: MVP 核心终端（W1-W10）

| 周次 | 任务 | 交付物 | 验收条件 |
|------|------|--------|----------|
| W1-2 | 项目脚手架搭建，GPUI 窗口框架 | 可运行的空壳应用 | `cargo run` 启动窗口 |
| W3-4 | PTY + VT 解析集成 | 终端可显示输出 | 执行 `ls`/`cat` 正确渲染 |
| W5-6 | SSH 连接 + 认证 | SSH 登录可用 | 密码/公钥认证成功 |
| W7 | 终端 GPUI 渲染 | 终端视觉可用 | 256 色正确显示 |
| W8 | 会话管理 CRUD | 会话可保存/加载 | 会话持久化到 TOML |
| W9 | 标签式多会话 | 多标签并行 | 同时开 3+ 会话 |
| W10 | 测试与优化 | Phase 1 发布 | 无 P0/P1 Bug |

#### Phase 2-6 类似结构，参见 `03-detailed-design.md` §7

## 4. 风险识别与应对策略

### 4.1 技术风险

| ID | 风险描述 | 影响 | 概率 | 应对策略 |
|----|----------|------|------|----------|
| TR-1 | GPUI 框架不稳定，API 频繁变更 | 高 | 高 | 封装 GPUI 适配层；关注上游动态；必要时 fork |
| TR-2 | 终端渲染性能不达标（大量输出时卡顿） | 高 | 中 | 字形图集缓存、批量绘制、异步渲染；参考 Alacritty |
| TR-3 | ConPTY (Windows) 兼容性问题 | 中 | 中 | 早期 PoC 验证；备选方案：WinPTY |
| TR-4 | russh 库功能缺失或 Bug | 高 | 中 | 提前验证核心功能；准备 ssh2-rs 作为备选 |
| TR-5 | WASM 插件性能开销过大 | 中 | 低 | 关键路径用动态库插件；WASM 仅用于非性能敏感扩展 |
| TR-6 | 跨平台字体渲染差异 | 中 | 中 | 使用 font-kit 统一抽象；内置等宽字体 |

### 4.2 进度风险

| ID | 风险描述 | 影响 | 概率 | 应对策略 |
|----|----------|------|------|----------|
| SR-1 | 终端仿真复杂度超出预期 | 高 | 中 | 复用 alacritty_terminal；Phase 1 先支持 xterm-256color |
| SR-2 | GPUI 组件库缺少所需组件 | 中 | 中 | 提前盘点组件需求；自定义实现缺失组件 |
| SR-3 | 核心开发人员离职/不可用 | 高 | 低 | 完善文档；模块化设计降低耦合；知识共享 |
| SR-4 | 第三方库重大 Breaking Change | 中 | 中 | 锁定版本；封装适配层；定期更新依赖 |

### 4.3 依赖风险

| ID | 风险描述 | 影响 | 概率 | 应对策略 |
|----|----------|------|------|----------|
| DR-1 | GPUI 项目停止维护 | 致命 | 低 | 关注社区 gpui-ce fork；评估 iced/egui 作为备选 |
| DR-2 | russh 不兼容 OpenSSH 新版本 | 高 | 低 | 参与上游贡献；备选 ssh2-rs (libssh2) |
| DR-3 | 许可证冲突 | 中 | 低 | 提前做许可证审计（见可行性报告） |

### 4.4 风险矩阵

```
影响 ↑
致命 │  DR-1
     │
 高  │  TR-1,TR-4  SR-1,SR-3  TR-2
     │
 中  │  TR-3,TR-6  SR-2,SR-4  DR-2,DR-3
     │
 低  │  TR-5
     │
     └──────────────────────────────→ 概率
        低          中          高
```
