## 术语：连接信息与标签会话

这两个概念此前混用同一个词「会话」，导致「多开终端窗口」「复制会话」到底改了什么说不清。现固定为：

- **连接信息**：左侧「连接」面板里的一个条目 = 主机 / 端口 / 用户 / 协议 / 认证方式 / 分组。它是**可复用的连接配方**，本身不持有任何运行时会话。代码里的 `SessionConfig` / `list_sessions` 等命令名属于历史协议契约，本轮不改名（跨层重命名是另一个量级的改动），但界面一律称「连接」。
- **标签会话**：终端工作区里的一个标签 = 一次**独立的会话实例**，有自己的 `attach_terminal` 通道、终端缓冲区与连接状态。同一份连接信息可以同时开多个标签会话；关掉其中一个不影响其余。

由此，三类动作的归属就清楚了：

| 动作 | 作用对象 | 结果 |
|---|---|---|
| 标签右键「新建标签」 | 当前聚焦标签的连接信息 | 多一个独立标签会话 |
| 标签右键「复制标签」 | 右键所在标签的连接信息 | 多一个独立标签会话（不新建连接条目） |
| 连接列表右键「复制连接信息」 | 连接条目本身 | 新增一条连接信息（凭据不复制，需补录） |
| 标签右键「关闭标签」 | 该标签 | 只关这一个会话实例 |

## SSH 输入超时与手动恢复

SSH 每个标签的输入与 resize 使用 10 秒端到端预算，包含核心层客户端锁、队列入队与协议执行；关闭标签绕过该标签的输入队列，客户端锁等待上限为 10 秒，整条 SSH 连接断开的锁等待与执行上限为 15 秒。尚未开始且已过期的请求会被丢弃，发生超时或部分写入时旧标签路径隔离，不自动重放输入。

一次 `terminal_recovery_required` 错误即在终端显示持续的“输入结果不确定”提示，暂停键盘、退格与粘贴。手动重连会实际断开旧连接，建立新连接并重新附加终端；只有这些步骤成功才恢复输入，失败保留提示与重试入口。远端可能已执行部分字节，重连无法撤销它们，也不恢复原进程。

附加标签故障只隔离其 PTY；主标签输出结束沿用现有整条连接拆除契约，因此同连接的其他标签会看到真实断开状态。手动重连替换整条连接，其他标签通过真实连接事件重新打开并附加各自 PTY。独立连接不共享故障标签的队列、取消信号或客户端锁。macOS 实机 SSH、多标签与网络故障验收仍待执行，Windows 自动化结果仅为开发验证。

## 已接通的能力

- 应用级快捷键（唯一定义处 `utils/shortcuts.ts`）：`Ctrl+N` 新建连接、`Ctrl+F` 查找、`Ctrl+Shift+C` 复制、`Ctrl+Shift+V` 粘贴。工具栏 title 上写的快捷键都以此为准——此前「新建连接 (Ctrl+N)」只是提示，按了没反应。应用接管的键**不再送进远端 shell**（此前 Ctrl+F 会同时往 shell 里塞一个 0x06）；Escape 不属于应用快捷键，仍照常送给远端（vim / readline 都要）。在普通输入框（对话框、搜索框）里打字时应用快捷键不抢。
- 应用图标：圆角蓝底 + 终端提示符「>」的标记，由 `scripts/gen-icons.mjs` 用纯 Node（内置 zlib）光栅化生成 PNG(16…1024) / ICO / ICNS，`npm run icons` 可复现。此前 `src-tauri/icons/*.png` 是**占位图**（32×32 仅 104 字节、纯色/全透明），因此 dev 与打包后的窗口、任务栏、exe 都不显示图标；标题栏的 logo 也曾是文字字形 `⌬`，现为与图标同款的内联 SVG。
  **改了图标必须让 tauri 的 build script 重跑**：图标是编译期资源，`tauri_build::build()` 把它们写进 OUT_DIR 生成的 Rust 源码，但 cargo 只按 `build.rs` 自身指纹决定是否重跑该脚本——只改 `src-tauri/icons/*.png` 不会触发它，增量构建的 exe 与安装包**仍带旧图标**（实测：图标已是真图、exe 也重新链接，抠出来仍是纯色方块）。`npm run icons` 末尾会自动 `touch src-tauri/build.rs`；已经手动改过图标文件时执行 `touch src-tauri/build.rs`（或 `cargo clean -p rshell`）再构建。验证方式：Windows 上用 `[System.Drawing.Icon]::ExtractAssociatedIcon(exe).ToBitmap().Save(...)` 抠出内嵌图标直接看，不必靠肉眼判断任务栏。
  **安装器自身的图标要单独配**：`bundle.icon` 只决定应用本体与图标资源，**不会**自动给安装器指定图标——不配 `bundle.windows.nsis.installerIcon` 时生成的 NSIS `installer.nsi` 里是 `!define INSTALLERICON ""`，setup.exe 会用 makensis 的默认图标（经典 NSIS 箭头圆标），看起来与软件无关。MSI 侧无需额外配置：WiX 的 `main.wxs` 已把 `ProductIcon` 指向 `resources\icon.ico`。另注：`tauri.conf.json` 不接受注释键（schema `additionalProperties: false`，写 `"//": "..."` 会被直接拒掉），这类说明只能记在文档里。

- SSH/Telnet/Serial 会话保存、恢复、连接、断开和终端 I/O。Telnet 的子协商按 RFC 1091 应答：客户端对 `DO TERMINAL-TYPE` 回 `WILL` 后，服务器发 `SB TERMINAL-TYPE SEND` 时必须回 `SB TERMINAL-TYPE IS <类型>`——此前子协商内容被整段丢弃，客户端答应了却从不真发，是一次「说了要做却没做」的假承诺。SSH 的认证方式有四种：密码、托管密钥、外部私钥、键盘交互（后端 `AuthMethod::KeyboardInteractive` 与 SSH 客户端的交互式认证流程早已实现，此前界面没有这个选项，该能力等于无法使用）。Telnet 协议层不带凭据，服务器若要口令由终端内交互输入。串口设备由系统枚举（`ListSerialPorts`）后在下拉里选，不必手打 `/dev/cu.usbserial-XXXX`——插拔一次名字就变；枚举失败时保留手工输入并说明原因。
- 终端搜索、清屏、尺寸同步、发送与状态更新。搜索栏显示**匹配计数**（当前第几个 / 共几个，无匹配时明说「无匹配」），并可切换「区分大小写」——此前只有输入框与上/下一个按钮，用户不知道有没有命中、当前在第几个。
- 终端面板短标签：会话名优先（超长按字符截断加省略号），无会话名时退回首 8 位会话 id。会话改名后重新激活会同步刷新标签。
- 文件面板路径栏三入口：面包屑跳转、就地输入绝对路径（回车提交 / Esc 取消 / 越界与相对路径当场说明原因）、目录树下拉（逐层懒加载，打开时把当前路径所在链展开，可按目录名筛选）。目录读取失败在节点上显示真实原因，不伪装成空目录。
- 文件列表上下左右滚动：高度由容器实测喂给 `el-table`，表头固定、滚动条贴着表格，窄面板走横向滚动而不是把列挤扁。
- 传输面板「日志」tab 显示真实事件流（入队、暂停/继续/取消/删除、批量清理、目标冲突、完成、失败、队列读取失败、订阅失败），带时间、等级与明细，可清空；超出环形缓冲容量时丢最旧条目并显示「更早还有 N 条已被丢弃」，空状态只说「暂无日志记录」不用占位文案冒充内容。
- 传输面板顶边可拖动调整高度（120px ~ 父容器减 140px），双击恢复默认 220px，窗口外松手也能收尾。
- 全局自定义弹窗：确认/输入窗体与本地文件（夹）选择器都在应用内渲染（`utils/dialog.ts` + `components/dialogs/`），不再出现 Element Plus 的 `ElMessageBox` 窗体，也不再调用 `tauri-plugin-dialog` 的原生 `open()` / `confirm()`。本地选择器走已声明的 `fs:read-all` 直接读目录，支持面包屑、手工输入路径、目录树、隐藏项过滤与新建文件夹，读取失败显示真实原因。仍有三个窗体保留 Element Plus 的 `el-dialog`（新建会话表单、主机密钥指纹对比、更新凭据）：它们本就是应用内组件而非系统窗口，且已随 `styles/element-plus.css` 适配主题；主机密钥对比窗的指纹对照表布局属于安全关键信息，改为纯文本窗体是信息降级，本轮不动。
- 终端外观设置（「设置 → 终端」）：字号、字体预设、光标样式与闪烁、滚动回滚行数可改，**对已打开的终端立即生效**（xterm 的这几项都能在运行时改），偏好存本机 localStorage（与「选中即复制」同一套机制）。此前这些值在 `TerminalPane` 里写死，`TerminalConfig` 类型声明了同样字段却从未接线——类型在承诺一个不存在的能力。
- 终端：右键无选区时直接粘贴、有选区时弹菜单（复制/粘贴/清屏）；连接状态跟随后端 `ConnectionStateChanged` 渲染，断开时禁用输入、给出可重连入口。**终端上不摆配置控件**——配色方案与「选中即复制」在「设置 → 终端」面板（`TerminalSettingsPanel`），改完已打开的标签立即生效（偏好经 `utils/terminalPrefs` 的模块级 ref 共享，连接状态的常驻展示交给窗口底部 StatusBar）。
- 同一条连接信息可同时开多个标签会话（面板 id 带 `~n` 序号、标签带 `#n`，关掉中间窗口后编号自动补齐）；连接列表右键可「复制连接信息」用同一份配方建新条目。
- SFTP 远程浏览、本地目录授权、单文件上传下载、新建目录、普通文件删除和真实队列。远程/本地文件列表支持右键菜单：本地列表给「上传到远程」，远程列表给「下载到本地/新建文件夹/删除/刷新」；多选普通文件可一次批量入队（目录与不安全名称自动剔除），单条失败不阻断其余文件，失败条目汇总提示。
- Local/Dynamic SSH 隧道，旧 Remote 规则兼容拒绝。
- 隧道的挂起与恢复、待定隧道的显式恢复：挂起会撤销已建立的转发连接并停止接受新连接，恢复会换用新的取消通道（否则恢复出来的隧道一出生就处于已取消状态）。应用重启后不自动抢占端口，只把用户意图记在 `tunnels.toml`；界面「待恢复的隧道」区块把这些规则逐条列出并提供「恢复」，此前界面只显示被跳过的旧规则，可恢复的规则从不显示。
- 主机密钥确认与永久保存、SSH 密钥管理接口。托管私钥已接入会话认证：新建连接时选「托管密钥」，连接时后端按 `managed_key_id` 经 `KeyManager` 取私钥字节（见下文「凭据与密钥」节）。
- 已信任主机密钥的查看与删除（「设置 → 安全」）：后端此前只有 `delete_host_key` 命令、界面上没有任何入口，而 known_hosts 位于应用数据目录内、用户不直接编辑它；现补 `list_host_keys` 命令与对应面板，删除走应用内确认窗，且只影响本应用的 known_hosts，不动用户 `~/.ssh/known_hosts`。面板还显示每条目的「上次连接时间」——该时间戳放在 `<known_hosts>.meta.json` sidecar 里（known_hosts 本体必须保持 OpenSSH 标准格式才能与 `ssh-keygen` 互操作，标准格式没有放时间戳的位置），连接成功后更新；不设 sidecar 的话 `first_seen`/`last_seen` 每次重启都会被重置成「现在」。
- SSH 公钥导出：密钥面板每行有「导出公钥」，公钥经 `PublicKeyExported` 事件回传后可一键复制。**私钥本体永不过 IPC**（只出 `SshKeyInfo`）。
- 连接分组：分组是真正的实体（`Folder`），持久化在 `folders.json`；连接列表按分组建树，可新建分组、删除分组，新建/编辑连接时可选择所属分组。**删除分组不会删除连接**——组内的连接回到「默认」，凭据不变。分组名不允许为空或与既有分组重名（大小写不敏感）；分组文件损坏时保留原文件不动，只记 warn。
- 连接信息的编辑：连接列表右键「编辑连接」可改名称、主机、端口、用户名、认证方式、分组与串口参数。密码与密钥口令留空表示**保持现有凭据不变**（凭据本体读不出来，留空不能当成「清空」）；填入新值才会替换钥匙串里的那一条。连接进行中不可编辑（后端拒绝并给出真实原因）。此前只能改凭据，改主机名只能删掉重建——凭据随连接 id 走，一并丢掉。
- 快速命令、触发器创建、删除、执行/开关与持久化。快速命令的作用范围有当前会话 / 所有已连接会话 / 选定会话三种（后端 `QuickCommandScope` 三种变体都能创建）。
- 快速命令的分组与说明：创建时可填「分组」与「说明」，面板按分组名把命令聚在一起（同名的归一组，没填的归「未分组」）。后端 `QuickCommand.group` / `description` 此前恒为 `null` / 空串——字段存在却没有任何界面能设置。
- 快速命令热键：创建时可绑定 `Ctrl+Shift+1` 这类组合键，命中后按该命令的**作用范围**执行（与面板里的「执行」按钮完全一致，共用同一套范围解析）。修饰键必须完全一致才命中（按 `Ctrl+1` 注册的不会被 `Ctrl+Shift+1` 触发）；在输入框里打字不算触发；应用自身的快捷键（复制/粘贴/查找）优先。热键写法无法识别时当场说明，不静默存一个永远不触发的绑定。触发器可单独命名（留空则沿用匹配条件）；匹配条件（正则 / 包含文本）与四种动作（发送文本 / 显示通知 / 断开连接 / 记录到文件）都能在界面上创建；「记录到文件」要求绝对路径且带文件名（后端同样校验），路径用应用内文件选择器选取。条件标签按**实际行为**命名：后端的 `TriggerCondition::ExactMatch` 实现为「输出片段包含该文本」（输出是任意分片，等值比较几乎不会命中），因此界面叫「包含文本」而不是「精确匹配」。
- 同步输入（「工具 → 同步输入」）：勾选一组会话后，任意终端的输入会同时发到这组会话（每个目标会话发到它的**主** pty；源会话所在的那个标签不影响其它标签）。
- 远端浏览复用同一条 SFTP 通道：浏览目录 / 取 home / 取元信息共用一条 SFTP 会话，不再每次新开通道 + 重做版本握手（服务端还要为每条通道 fork 一个 sftp 进程）。SFTP 的 I/O 不在 `SshClient` 的锁里做——列一个慢目录不会把同会话的 resize 一起堵住。会话失效时只读操作会丢弃缓存重开一条再试一次，写操作（建目录 / 删文件）**不重试**（可能已生效，重试会报「已存在 / 文件不存在」这种假失败）。**源会话不重复收到**（此前源会话在同步列表里时输入会被发两次，远端因此执行双份字节）；某个目标发送失败会发布 `SyncInputSendFailed` 事件并给出全局提示，不静默吞掉。同步会话组只存在于后端内存，重启后自动关闭。
- 撰写窗格（「工具 → 撰写窗格」）：编辑多行文本，一次性发到当前会话 / 全部会话 / 选定会话。全部目标失败时 invoke 直接报错，部分失败时逐个会话列出失败原因。
- Rhai 宿主发送、列会话、执行快速命令接口。
- Rhai 脚本运行器（「工具 → 脚本」）：选一个目标会话、写一段脚本、运行、看结果；面板同时列出脚本可用的 `rshell_*` 宿主函数与能力边界（无文件读写、无网络、有操作数与时间上限）。这不是完整的脚本 IDE。
- 主题、终端配色与事件订阅释放。
- 终端配色方案的导入（「设置 → 终端 → 导入…」）：读取本地 JSON 方案文件（颜色为 `0xRRGGBB` 整数），导入后**写入本机持久化文件**，重启后仍在方案列表里；解析失败会指出具体是哪个字段不合法。主题与配色方案的**选择**仍不承诺跨进程恢复。
- 本地 WASM 插件发现、清单解析、编译加载与卸载。**扫描时被拒的插件目录**（清单解析失败、目录名与清单 `name` 不一致）会以「错误」状态出现在列表里并带上原因——此前只记一条 warn 日志就跳过，用户扫描插件只看到「没有插件」，不知道自己的目录被拒了。插件面板展示清单**声明的权限与扩展点**，并明确说明「已加载」只表示模块编译并登记成功——当前宿主不向 WASM guest 提供任何宿主能力（网络 / 文件系统 / 会话 / 终端 / 剪贴板 / 进程均未实现），清单里声明的权限不会生效。此前这些数据经 IPC 传到了前端却从不展示，用户只看得到「已加载」。

## 核心接口与界面边界

API 类型与后端实体保持一一对应：两侧都不再保留零引用的类型（`TerminalConfig`/`CursorStyle`/`SearchMatch`/`TelnetConfig`/`SessionInfo` 两侧都是 0 引用），也不保留恒为零且无人消费的字段（`ConnectionInfo` 的 `bytes_sent`/`bytes_received`/`latency_ms` 始终是 0/None，界面从不显示）——删掉后类型镜像不再声明不存在的能力。

触发器界面提供正则匹配后发送文本；通知、断开和日志动作由核心 API 提供。Rhai 有脚本运行器（选会话、写脚本、运行、看结果）但没有完整脚本编辑器：没有工程管理、没有断点、没有补全，宿主能力只有面板列出的那组 `rshell_*` 函数。WASM 加载不等于扩展点或宿主权限已执行，没有虚假的启用/禁用入口。

SSH 密码和密钥口令存放在 macOS 钥匙串（Keychain），会话 TOML 只保存凭据存在状态等元数据。读取旧版会话时会将其中的明文密码/口令迁移到钥匙串，并重写会话文件以移除秘密。迁移失败保留原文件并在会话列表显示持久加载问题，修复访问权限或配置后可点击“重试加载”。钥匙串条目缺失时连接失败关闭；用户可在会话列表右键选择“更新凭据”，重新输入密码或私钥口令，点击“保存凭据”后重新连接，不会从旧文件回退读取。此入口仅接收新凭据，不显示已存储的秘密。钥匙串不可访问时须先修复 macOS 钥匙串访问权限。macOS 可能在钥匙串访问时显示系统授权提示。主密码仅用于应用锁定/验证，不是凭据保险库，也不加密钥匙串。钥匙串系统提示、旧版数据迁移及缺失凭据恢复尚无 macOS 人工验收记录。主题选择和传输队列不承诺跨进程恢复。触发匹配以 UTF-8 输出片段为单位，不保证跨分片模式匹配。

### 凭据恢复与主机密钥请求生命周期

连接错误现在保留机器可读的恢复类别：`credential_missing`（条目缺失，连接列表已有「更新凭据」入口）、`credential_inaccessible`（系统钥匙串不可访问，提示修复访问权限后重试）、`credential_save_failed`（保存被拒绝，编辑器保留输入且不建立连接）、`credential_migration_failed`（旧配置迁移失败，显示脱敏原因并提供重试加载）、`auth_failed`（服务器拒绝认证）、`connection`（网络/传输失败）、`host_key_mismatch`（主机密钥未获接受）以及 `host_key_trust_persistence_failed`（永久信任落盘失败）。Rust `CoreError` 到 Tauri `IpcErrorKind` 使用稳定字符串映射，前端只按 kind 分支，不解析 message，也不会显示或记录秘密。

凭据保存成功不等于连接成功，也不会自动重连；用户必须显式重新连接。错误提示不会伪造 `Connected` 事件。取消凭据编辑不调用写入命令。旧配置迁移失败保留原文件和可重试的脱敏诊断，不回退到旧明文。

主机密钥请求以 `decision_id` 为键，而不是单一 current 请求。生命周期为：`Pending` → `DecidedTrustOnce`、`DecidedTrustAlways`、`DecidedReject`，或用户取消后的 `Cancelled`，协议等待超时后的 `Expired`，以及前端对已失效项的本地 `Dismissed`。每个请求独立注册、提交、取消和过期；一个请求的确认/拒绝不会接受或清除另一个请求。显式取消会发送 keyed `CancelHostKey` 并取消对应协议等待；后端取消/超时通过 `HostKeyDecisionStateChanged` 通知前端，未知或已过期 id 的迟到事件被丢弃。永久信任先以 CAS claim 保存到 trusted store，只有落盘成功才发送接受握手；落盘失败会释放请求回 `Pending`，保留错误并允许用户改选「信任一次」或取消，期间绝不发布 `Connected`。

私钥保存在应用数据目录的 keys_dir（生成/导入时提供口令则以 OpenSSH 加密格式落盘）。托管私钥与会话的关联通过 `AuthMethod::PublicKey` 的可选 `managed_key_id` 表达：新建连接「认证 → 托管密钥」选择后，连接时 `SessionService` 按 id 经 `KeyManager::get_private_key_data` 取私钥字节，协议层用 `russh::keys::decode_secret_key` 内存解码认证（与磁盘 `load_secret_key` 同一执行路径，loopback 服务器测试覆盖）；口令沿用会话自己的钥匙串槽位（`session:{id}:passphrase`，「更新凭据」弹窗补录）。私钥字节仍不过 IPC、不进 `SessionConfig`（`SshKeyInfo` 白名单测试不变）。密钥被删除后引用它的会话连接时报「no longer available; re-select a key」，不冒充可重试的连接失败。磁盘私钥路径模式（`key_path`）保持原语义，旧 TOML 不受影响。

### 主密码与应用锁定

主密码**只用于应用锁定与验证**，不是凭据保险库，也不加密 macOS 钥匙串里的会话密码或私钥口令——界面必须如实说明这一点，不能让用户以为设了主密码就能保护钥匙串。

「设置 → 安全」面板提供设置、修改、停用与立即锁定。停用必须提供**当前**密码：没有当前密码就能停用等于给锁留了一个绕过口。忘记密码的恢复路径是删除数据目录里的 `master_password.json`（本机操作），界面**不提供**一键重置按钮——有重置按钮的话锁等于没有。

持久化的是盐与加密后的验证令牌（`master_password.json`，Unix 权限 0600，同目录临时文件 + rename 原子提交）。**派生密钥永不落盘**：重启后状态是「已锁定」，必须重新输入主密码解锁。这一条是主密码能否算「真的实现了」的分界线——只把状态放在内存里的话，「设置主密码」跨重启即失效，属于静默假成功。

锁定态下整块工作区被遮罩盖住，必须输入主密码才能继续使用。锁定是**应用层**锁：它挡住的是这台机器上的操作入口，不会断开已经建立的 SSH 连接，也不阻止钥匙串被同一账户下的其它进程读取。因此它保护的是「别人直接动手操作这台机器上的会话」，不是「会话凭据本身」。

命令契约：`SetupMasterPassword` / `VerifyMasterPassword` / `ChangeMasterPassword` / `DisableMasterPassword` / `LockMasterPassword` / `GetMasterPasswordState`（返回 `NotSet` / `Locked` / `Unlocked`）。写盘失败时 `SetupMasterPassword` 与 `ChangeMasterPassword` 直接报错，不报成功——否则重启后主密码会凭空消失。持久化文件损坏或版本不符时忽略该文件并保持 `NotSet`，不让应用启动失败。

传输队列界面提供可见的「暂停/继续/取消/重试/删除」操作，分别调用 `PauseTransfer`/`ResumeTransfer`/`CancelTransfer`/`RetryTransfer`/`RemoveTransfer`。前三者通过按任务的 `watch` 控制通道驱动 staged lifecycle 拷贝循环；「重试」由专用的 `RetryTransfer` 命令入口（**不**复用 `EnqueueUpload`/`EnqueueDownload` 配 hidden flag），从零创建新任务 id 并强制使用 `Fail` 策略，让 staged lifecycle 提交前再检一次冲突；「删除」只把**终态**（完成/失败/已取消）条目移出队列列表，不删除本地或远端已传输的文件；活跃任务调用会返回 `InvalidState`，必须先取消。未知条目重复删除按幂等处理，不报错。失败 / 已取消的终态任务上额外显示「重试」按钮（仅这两个终态——「完成」不提供重试，避免「重看结果」误解）。面板标题栏另有队列管理菜单，可按「清除已完成/失败/已取消/全部已结束」批量移除，并显示各分组当前条数；批量逐条调用 `RemoveTransfer` 而非新增批量命令，以便部分失败可见（否则用户会以为已清空而实际仍有残留）。进行中的任务在任何分组里都不会被批量清除。

R2-T2：上传与下载都跑「独占打开 staging temp → 字节拷贝 → 提交前再检查冲突 → 安全提交（rename）→ 失败/取消时清理 temp」这个完整生命周期。temp 文件路径形如 `<target>.partial-<task_uuid>`（同目录，便于跨平台 rename 都是同文件系统内操作），任务独占创建（O_EXCL / `OpenFlags::EXCLUDE`）。提交前再次检查目标是否存在——预检通过后目标出现会触发 `late_conflict` 并清理 temp、保留旧目标。取消与提交由 `cancel_decision: AtomicU8` 仲裁：commit 发送之前取消到达 → 取消胜出、commit 不发送、旧目标保留、temp 清理；commit 已在飞（已发出 rename） → commit 完成即收尾（取消意图被吞，因为目标已被替换）。「100% 字节进度」**不**代表提交成功——commit 失败时 `error_message` 与 `cleanup_status: "residue"`（含 temp 路径）一起返回给前端，告知用户残留临时文件的**确切位置**与清理失败原因，**不**静默吞掉。该行为由 staged lifecycle（`rshell-core/transfer/staged.rs`）的 13 条 RED-first 回归测试 + 服务层 retry 入口的 3 条测试覆盖。进程被强杀 / 断电 / 清理本身失败时，staging temp 会留在磁盘上——正常路径没有任何代码会再碰它。为此每次传输收尾时会扫描目标所在目录（远端目录走 SFTP、本地目录走文件系统），回收**超龄的孤儿** `.partial-<uuid>` 文件：名字必须是 `<本次目标名>.partial-<合法 uuid>`（同目录里其它目标的孤儿不在回收范围内——上次崩溃留下的 `b.txt.partial-<uuid>` 要等下次传 `b.txt` 时才被清掉）、必须是普通文件（目录与符号链接不碰）、mtime 必须早于阈值、且其 task id 不属于本进程的在途任务。阈值本地 1 小时、远端 24 小时（远端 mtime 来自服务器时钟，与本地可能差很多，阈值短了会误删对方刚写的同名临时文件）。回收是尽力而为，失败只记日志，不影响传输任务的终态。提交语义：提交需要能发 `SSH_FXP_EXTENDED` 的 raw 会话（`russh_sftp::client::RawSftpSession`——高层 `SftpSession` 不暴露内部 raw 句柄，但 raw 类型本身是公开 API），因此除数据通道外还要一条 SFTP 通道。这条**提交通道改为惰性开启**：提交那一刻才临时开一条短命通道，握手 → 探测扩展 → 发一次 rename → 立刻释放。传输期间（往往是几十分钟）每个任务只占 1 条 SSH 通道——原先每个传输任务常驻占 2 条，很容易撞上服务端 `MaxSessions`（OpenSSH 默认 10，按连接计，同会话的终端标签页也抢同一额度）。配套地，同一会话上的并发传输任务上限为 3（`MAX_CONCURRENT_TRANSFERS_PER_SESSION`）：超出的任务在**不占用任何通道**的前提下排队，而不是被服务端拒绝 channel-open 直接失败。版本握手（SSH_FXP_VERSION）里服务器声明 `posix-rename@openssh.com` 时，提交走 `SSH_FXP_EXTENDED`（请求体为 oldpath/newpath 两个连续 SSH string），获得**协议保证的原子替换**；服务器以 `SSH_FX_OP_UNSUPPORTED` 拒绝（探测与实际行为不一致的兜底）或没有提交通道时，回退标准 `SSH_FXP_RENAME` 并如实报告 `standard_rename`。posix-rename 的其它失败（网络、权限）不回退直接报错——超时类失败语义是「结果未知」，盲目重试 rename 可能掩盖真实原因。提交通道打不开只降级不失败。提交策略经 `commit_strategy`（`posix_rename` / `standard_rename`）透传到前端。以上提交语义与回收安全性已在真实 OpenSSH 9.6 与 GNU inetutils telnetd 上验证（见 [macOS 验证记录](09-macos-validation.md) 的 2026-10-22 节）。提交语义由提交路径自己探测后如实回报（`CommitOutcome`），不再由调用方传入一个恒为空的能力参数。wire format 与应答映射有单测锁定；真实 OpenSSH 服务器上的行为验证仍属待验收（见「尚待真实环境验收」）。详见 `docs/research/2026-10-08-sftp-staged-commit-report.md` 的 capability 调查结论（其「未找到 raw handle 路径」的结论已被上述第二条通道方案取代）。

远端文件面板默认打开登录用户的工作目录，而不是文件系统根 `/`：新增 `GetRemoteHomeDir` 命令，用 SFTP `realpath(".")` 解析（sftp 子系统启动时的当前目录即用户 home，远端无需额外支持 `~` 展开），解析失败回退 `/` 并在前端保持当前目录，不把远端面板打成空白。外部显式传入 `remotePath` 时不覆盖。

本地目录记忆上次打开位置：存 `localStorage`（纯 UI 偏好，无跨进程/跨设备一致性要求），仅接受绝对路径并归一化尾部分隔符，存储不可用时降级为「不记忆」且不抛错。记忆的目录若已失效，错误由面板错误行显示真实原因，用户可点「更换」重新选择，不静默清空。

右键上传/下载时，**先读一次目标目录**（远端经 `BrowseRemoteDir`、本地经 `readDir`）拿到已存在的文件名；命中同名就在入队前弹自定义窗体让用户选「跳过 / 重命名… / 覆盖」，覆盖是破坏性操作用危险样式。目录读不到（权限、断线）时不假装无冲突，仍按 `Fail` 策略入队，由后端的 `target_exists` 兜底再问一次——预检只是省掉一次往返，不是唯一防线。

删除类操作一律走应用内确认窗（会话、SSH 密钥、快速命令、触发器、远程文件、非回环隧道暴露），破坏性按钮用危险样式；输入类弹窗校验不通过时窗口保持打开并就地显示原因，不静默关掉让用户重输。弹窗服务用 FIFO 队列：解决一个弹窗的回调里会立刻再弹一个（冲突确认 → 重命名输入），单槽会把前一个 Promise 永远悬着。

### 本地文件系统权限（全局读写）

Tauri 的 fs scope 分「命令权限」与「路径 scope」两层。此前 capability 只声明了 `fs:allow-read-dir` / `fs:allow-stat` 且**没有任何路径 scope**，而 scope 是运行时状态：`tauri-plugin-dialog` 只在用户点选目录时自动 `allow_directory`，进程重启后即为空。后果是「上次打开的目录」从 localStorage 恢复时没有经过对话框，读取被拒（`forbidden path: ...`，该提示仅在 debug 构建出现，release 返回 `PathForbidden`）。

按产品决定改为**默认全局可读可写**：capability 声明 `fs:read-all` + `fs:write-all`，并加一条 `{ "identifier": "fs:scope", "allow": ["**"] }` 覆盖全部路径。`deny` 优先于 `allow`（tauri 先判 `is_forbidden`），因此同时保留 `fs:deny-webview-data-windows` / `-linux`，WebView 自身数据目录仍不可读写。

风险边界（如实记录）：授予的是应用自身 WebView 的权限，`fs:write-all` 包含 `mkdir`/`create`/`copy_file`/`remove`/`rename`/`truncate`/`write*`，即 WebView 可创建、覆盖、**删除和重命名**进程权限范围内的任意文件。本应用以自己的进程权限运行，该范围与 Xftp/WinSCP 等同类工具一致。`tests/unit/capabilityScope.spec.ts` 锁定三项：存在 `**` scope、读写权限未被收窄、WebView 数据目录仍在 deny 列表。

终端复制粘贴快捷键为 `Ctrl+Shift+C` / `Ctrl+Shift+V`（macOS 另接受 `Cmd`），经既有的 `rshell:terminal-action` 路由到当前激活终端。裸 `Ctrl+C`（SIGINT）与 `Ctrl+V`（quoted-insert）不劫持，原样透传给远端。无选中内容或剪贴板为空时给出可见提示，剪贴板不可用时提示失败原因，不静默吞掉。

终端「选中即复制」是可选开关（默认开启，存 `localStorage`；存储不可用时只在本次运行有效并记 warn，不抛错）：每次选区变化去抖 150ms 后写剪贴板，选区清空不复制，写入失败只提示一次并提示可关闭该功能。终端右键按 Xshell 习惯处理：**没有选区时右键直接粘贴**（走 `term.paste()`，与键盘输入同等对待）；**有选区时**语义在「复制选中内容」与「粘贴」之间歧义，改为弹面板内菜单（复制/粘贴/清屏），避免刚选中的内容被一次粘贴顶掉。剪贴板为空、不可用或会话未连接时都给出可见提示，不静默吞掉；断线期间粘贴与键入都会被拦下。

终端配色在面板工具栏里下拉切换，选项来自后端 `ListThemes` 的 `available_schemes`，切换调用 `SetTerminalColorScheme`；方案被导入/卸载后可点「重新加载方案…」重新拉取。切换失败时 store 回滚并把 `error` 展示为提示，不假装切换成功。

终端面板的连接状态取自 `ConnectionStateChanged`（后端在远端 EOF、用户断开、会话删除等路径都会广播 `Disconnected`），不是本地猜测：只有「连过又掉」才显示断开条与「重新连接」按钮，避免新建面板时闪红条；断线期间 `term.options.disableStdin` 置真、界面加一层压暗，重连后自动恢复。`attach_terminal` 失败仍走原有的独立错误条（可重试附加），两者互不替代。

多标签会话：同一连接信息的第 n 个标签是独立 dockview 面板（id `terminal-<uuid>~n`、标签 `<连接名> #n`）。**每个标签是一个真正独立的 pty / 会话**：复用同一条 SSH 连接（不重新握手、不再弹主机密钥），但各自 `channel_open_session` + `request_pty` + `request_shell`，因此可以在不同标签里同时跑不同命令，输入与输出互不干扰。

寻址约定：终端以 `(session_id, terminal_id)` 二元组寻址。主 pty（首标签）以 `session_id` 作为 `terminal_id`；附加标签在 `addPanel` 时生成各自的 uuid，前端挂载时先 `open_terminal` 申请 pty、再 `attach_terminal` 注册字节通道，卸载时 `close_terminal` 释放（断开连接会一并关闭所有 pty）。后端 `TerminalChannels` 按二元组索引，attach 时补发该 pty 的滚动历史（上限 256 KiB），**新标签一挂上就有内容**（含 shell 提示符），不需要敲回车。输出**不**按会话扇出——那会让两个标签共用一份输出（即共享 shell），与「各自独立」相悖。

回归测试在壳层 `terminal.rs`：历史补发、**按 terminal 隔离**（一个 pty 的字节不进另一个 pty）、同 pty 多通道扇出（HMR 重挂）、失效通道单独摘除、按会话清理。终端标签的右键菜单由 dockview 的 `getTabContextMenuItems` 提供，含「新建标签 / 复制标签 / 关闭标签」；不提供该选项时 dockview 根本不弹菜单，「关闭标签」自己实现而不用内置项（内置项文案是英文 Close）。「新建标签」用当前聚焦标签的连接信息，「复制标签」用右键所在标签的连接信息，两者都只是多开一个独立标签会话、不新建连接条目。复制连接信息的流程放在 App.vue 而非连接列表组件：入口有两处（左侧列表、终端 tab），而列表是按侧栏当前面板条件挂载的，监听放在那儿会让 tab 触发的复制静默失灵。

复制会话：后端 `CreateSession` 直接采用 `config.id`（重复 id 会被拒为 `Session already exists`），因此复制必须在前端生成新 UUID，并把名称去重为「<原名> 副本」「<原名> 副本 2」。**凭据不随配置复制**——密码与私钥口令在钥匙串里不回读，后端也没有复制凭据的命令；口令类认证（Password / KeyboardInteractive）在创建后立即弹凭据对话框为新条目补录，密钥文件类认证不需要弹框但界面仍提示「凭据未复制（如需要请右键『更新凭据』）」，不会让用户以为复制完就能直接连。复制**不会自动选中或连接**新条目：新条目此刻没有凭据，自动连接只会得到一次注定失败的认证并弹出错误提示；连不连由用户点击决定。

SFTP 下载方向改为并发区间读取。根因是 `russh-sftp` 的 `File::poll_read` 只有一个在途 READ 槽，串行读取的吞吐上限为 `CHUNK_SIZE / RTT`；上传方向用 `write_nowait` 本就支持 `max_concurrent_writes` 路并发，因此下载长期明显慢于上传。现按 64 KiB 切分连续不重叠区间，最多 8 个 READ 同时在途，写入侧仍严格按 offset 升序串行，落盘内容与串行版本逐字节一致；小于 128 KiB 的文件退回串行以省掉多句柄开销。并发区间共用一个**远端句柄池**（整个传输只开 8 次句柄）——逐区间 `open` 会把 OPEN/CLOSE 放大到每 64 KiB 一对，1 GiB 文件就是 16384 次 OPEN + 16384 次 CLOSE，协议消息数是数据量的 3 倍；池空时退回现开一个，保证任务被中止丢句柄后读取不会永久阻塞。区间划分的连续/不重叠/完整覆盖由纯函数 `plan_ranges` 的测试锁定，句柄池的借还不泄漏/不超发/并发互异另有测试，错序完成、进度单调性、取消中止与源变短报错均有测试覆盖。**真实服务器上的实际吞吐提升倍数未验证**，局域网与跨网的对比数据待补。

### 传输吞吐

**根因：`tauri:dev` 产出的是 debug 构建，russh 的加密与缓冲处理在 debug 下慢一个数量级。** 这不是应用逻辑的限速，也不是 SFTP 层的并发问题。

在 `192.168.85.129`（Ubuntu，磁盘 689 MB/s，RTT < 1 ms）上实测（凭据从环境变量传入，基准见 `crates/rshell-protocol/tests/sftp_bench.rs`）：

| 场景 | 上传 | 下载 |
|---|---|---|
| debug 构建 | 2.54 MB/s | 2.44 MB/s |
| **release 构建** | **63.84 MB/s** | **45.22 MB/s** |

同链路 OpenSSH `scp` 上传对照为 31.88 MB/s。release 下上传已超过该对照，下载达到用户用 Xshell 观测到的同一量级。

**评估传输性能必须用 release 构建**（`npm run tauri:build` 或 `cargo build --release`），用 `tauri:dev` 测得的数字没有参考价值。

排查过程中用实验逐项排除了：SSH 通道窗口（2 MiB ↔ 16 MiB 无差别）、单包大小（32 KiB ↔ 65535 无差别）、密码套件（ChaCha20-Poly1305 / AES-256-GCM / AES-256-CTR 均 2.4～2.8 MB/s）、Nagle、服务端磁盘与网络。放大窗口与包长的改动已撤回——实测零收益且 65535 偏离 RFC 4253 建议的 ≤32768，会牺牲互操作性。

以下两项改动保留，它们本身是正确且有测试覆盖的，只是**并非速度问题的成因**：

- **下载并发区间读取**：`russh-sftp` 的 `File::poll_read` 只有一个在途 READ 槽，串行读取吞吐上限为 `CHUNK_SIZE / RTT`（上传方向则由 `write_nowait` 支持 8 路并发）。现按 64 KiB 切分连续不重叠区间、最多 8 个 READ 在途，写入侧严格按 offset 升序串行，落盘内容与串行版本逐字节一致；小于 128 KiB 退回串行。
- **远端句柄池**：逐区间 `open` 会把 OPEN/CLOSE 放大到每 64 KiB 一对（1 GiB 文件即 16384 次 OPEN + 16384 次 CLOSE）。现整个传输只开 `DOWNLOAD_CONCURRENCY` 次；池空时退回现开一个。
- **关闭 Nagle**：`russh::client::connect` 从不设 `TCP_NODELAY` 且 `Config` 无此开关，改为自行建连后 `set_nodelay(true)`。对交互式协议是正确做法，与 OpenSSH 一致；实测对吞吐无实质影响。

桌面构建入口仍为 `npm run tauri:build`，产物 Bundle ID 为 `com.letmlook.rshell`；本地与 CI 的预检/审计只走仓库脚本：

## 已知依赖风险：rsa 的 Marvin 时序攻击（RUSTSEC-2023-0071）

2026-10-08 的依赖升级把 `wasmtime` 提到 36.0.17、`russh` 提到 0.62，清掉了 20 项 RustSec 告警。剩下这一项**无法通过升级消除**，是本项目当前唯一的显式例外：

- 上游 RustCrypto/RSA 的 advisory 把 `patched` 有意留空：最新稳定版 `rsa 0.9.10` 与最新预发布 `rsa 0.10.0-rc.18` 均仍受影响。私钥信息可经**网络可观测的时序侧信道**泄漏。
- `russh` 的默认 feature 依赖 `rsa`。关闭它会失去 `rsa-sha2-256/512` 主机密钥算法，使仅提供 RSA 主机密钥的 SSH 服务器无法连接——对一个远程终端客户端是真实的互操作性回退，因此保留。
- 该风险记录在 [scripts/audit-ignored.txt](../scripts/audit-ignored.txt)，`scripts/audit.sh` 逐条回显到 stderr；清单之外的任何新告警仍然让 CI 失败。
- 复查条件：`rsa` 发布修复版本，或 `russh` 默认不再依赖 `rsa`。

本条只描述依赖状态，**不等于**已验证的抗侧信道能力；真实 SSH/SFTP 服务器场景仍见下文的未验证清单。

同一份审计另有 9 条 `cargo-audit` 归类为 **warning**（默认不阻断 CI）的传递依赖，现状如实列出，不作为「已解决」处理：

- `unmaintained` 8 条：`fxhash`、`proc-macro-error`、`smartstring`、`unic-char-property`、`unic-char-range`、`unic-common`、`unic-ucd-ident`、`unic-ucd-version`。均为构建期/间接依赖，上游停止维护，升级路径需逐个替换。
- `unsound` 1 条：`glib 0.18.5`（Linux GTK 传递依赖，修复版本为 0.20）。

这两类与 rsa 例外不同：它们是上游维护状态与单个 crate 的不健全标记，不是可利用漏洞，但确实意味着依赖树尚未现代化，后续应择机替换。
